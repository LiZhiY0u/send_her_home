# 双层灯阵 3D 交互原型设计

状态：用户已确认设计与实现计划，已选择直接执行。仅本地预览，不连接设备。

## 目标与边界

在现有微信小程序新增独立灯阵预览页面，用透明展示盒和上下各 133 颗灯表达预设灯效。保留原有五键遥控页面与蓝牙逻辑，不修改 ESP32、AppID、蓝牙协议，不烧录、不控制真实灯或电机。不实现单灯涂色、真实手办模型、真实反射阴影、保存预设及云服务。

## 方案选择

推荐小程序原生 Canvas WebGL 加 Three.js 适配层，直接验证最终运行环境。先用简单几何体，不加载外部模型或纹理。浏览器版本仅适合作快速视觉探索，不能替代小程序验证；Canvas 2D 透视投影可减少依赖，但不作为本次真 3D 实现的默认路线。

适配候选为 wechat-miniprogram/threejs-miniprogram 和 deepkolos/three-platformize。先进行版本、许可证和现有环境检查，锁定具体版本；尚未验证兼容性，不承诺直接可用。若需要额外开发环境安装，另行征得许可。

## 数据与尺寸

唯一灯位来源：仓库外层 docs/led-array-133/led-map-133.json。实现时将其可追溯副本纳入小程序资源，并记录来源与校验方式。验证单层 133 颗：中心 33、四角各 25；双层共 266，灯键使用 layer + channel + index，避免上下层编号冲突。

原数据单位 mm、平面尺寸 200×200mm，X 向右、Y 向上。3D 使用 X/Z 为水平面，Y 为高度。盒高暂用 300mm 作为可配置示意值，页面标注尺寸示意；不是用户确认的实物高度。顶部镜像与旋转参数独立配置，默认按世界坐标对齐作预览，实际安装方向待后续校准。

## 页面与交互

顶部始终显示“离线预览 · 不控制设备”。中央为透明盒体、手办占位几何体和 266 个灯位，发光用材质或轻量光晕示意，不为每颗灯创建真实点光源。

单指拖动旋转，双指缩放；提供整体、俯视、复位按钮。下方控制区按层级排列：顶部/底部/上下；全部/中心/四角（四角可分别选择）；常亮/旋转光线/扩散圆环；颜色、亮度、速度、播放/暂停。未选层淡化，区域选择采用明确按钮而非依赖遮挡下的三维拾取。

上下联动第一版仅实现同步与反向（旋转反向、扩散相位反向），不额外增加复杂编排。效果应用于选中层及区域，未选区域关闭效果预览但保留暗灯轮廓。颜色、亮度和速度属于当前预览设置，不代表设备状态。

## 代码边界

灯位映射、效果采样与渲染分离。纯函数根据坐标、效果参数和时间计算每颗灯的 RGB；场景只负责相机和绘制；页面负责表单和生命周期。纯算法便于以后移植到 ESP32，但本阶段不增加通信接口或虚构设备回执。

页面隐藏时停止动画；重新显示时恢复，不重复创建循环；退出时释放 GPU 资源和监听。WebGL 不可用时显示清晰错误与返回入口，不使用空白画面冒充成功。保留原遥控页面为默认入口，从其新增预览入口。

## 验收

自动测试覆盖灯数、区域计数、双层唯一编号、坐标变换、亮度边界、相位/方向，以及同一输入同一采样结果。开发者工具中检查触摸、表单和页面往返资源释放；Android/iOS 真机兼容与性能单独记录，未测试不声称通过。目标为典型手机流畅展示，先按 30fps 设计并限制像素比，实际帧率以测量为准。

用户验收：能看清上下层；旋转和缩放自然；三个效果与层/区域选择一致；关闭预览后原遥控功能不变。不得将灯珠预览理解为真实照度仿真或实物执行状态。
