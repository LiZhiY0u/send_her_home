# 单面软画笔绘画：使用与验证

日期：2026-10-21。第一版代码与主机验证，尚未完成手机/实物绘画验收。用户明确要求直接实现、不再多轮确认；未自动烧录、提交或推送。

## 如何看效果

1. 重新编译小程序。原遥控页点“底面灯板 · 实时绘画”，无需3D依赖也能先画；也可从灯阵实验室点“放大底面”，或点中3D底面。
2. 用手指画爱心，默认直径24mm；邻近灯按距线段的距离渐暗。可调10..60mm、选六种颜色、切换橡皮擦、清空。只画本地草稿时不控制设备。
3. 用户手动烧录本次固件后，点击“连接并同步绘画”。固件首次完整画面提交才暂停自动灯效；界面显示“设备已同步·帧N”代表收到应用确认。旧固件会提示不支持，不向五键通道发送绘画数据。
4. 返回后3D底面显示本次草稿；退出、隐藏或断连停止继续发包，灯板保留最后完整画面。再次进入需主动同步。草稿只在本次小程序内存保存。
5. “恢复自动灯效”显式切回扩散/旋转。清空只是黑色绘画帧，不恢复动画。重启ESP32恢复自动，未写Flash。

设备亮度上限仍26/255，画笔可能逐步覆盖全部133灯，确认电源能力及温升。此软件亮度不是电流保护。只控制当前 GPIO17 单链，顶部不下发。没有电机动作。

## 结构与协议

微信运行时数据使用JS模块，不直接require JSON。painting/physical-map.js与固件Diagnostics/LedPhysicalMap.h逐项校验相同，Lighting/PaintMapIdentity.h锁定映射哈希。屏幕Y方向翻转为世界Y向上。

ble/connection.js拥有全局连接和串行写队列，原FF11五键保留。绘画走FF12写入、FF13状态通知/读取。单帧399字节，分36个不超过20字节的包（BEGIN + 34个RGB块 + COMMIT），无需大MTU。

包头8字节：A7、版本1、命令、会话、帧号低/高、起始灯号、数量。命令1握手、2开始、3最多4灯RGB、4提交（附CRC16低/高）、5恢复自动。CRC16 CCITT-FALSE：初值FFFF、多项式1021，输入399字节RGB。状态16字节包含错误码、模式、会话、帧号、命令、32位映射哈希、133灯及26亮度。

收包暂存不直接输出。只有完整帧、范围及CRC正确才投递单槽画面邮箱；Lighting任务唯一写NeoPixel，show后ACK经BTstack线程发送。手机单帧在途、最多10Hz启动、只保留最新候选画面，实测速度取决于20字节写入延迟，不能将10Hz目标视为实物帧率保证。

## 验证边界

Node测试：软线段/边缘采样、坐标转换、JS/C++物理映射一致、分包/CRC已知向量、等待实际ACK与候选帧合并。

C++主机测试：缺块不提交、399字节完整帧、旧帧/错误会话/超时/越界、CRC已知向量；GATT属性表记录长度和handle一致。全部原固件与小程序测试必须继续通过。

独立只读审查提出两项传输问题，均补失败用例后修复：设备busy返回未执行第二次重试；旧取消握手的迟到回调误取消新会话。等待者现在绑定事务令牌，旧操作只能清理自己的等待者。

实际GATT发现/通知、手机触摸、3D拾取、写入吞吐、断连保持、OLED/手柄并行仍待用户验收。若升级固件后仍提示旧特征值，先断开重连并重启小程序；如系统缓存旧服务，可能需要重启手机蓝牙后重新发现。不得把主机模拟当成实物成功。
